Near-cap backup — main-thread probe

Answers the one question scripts/measure-backup-near-cap.mjs cannot: does the interface actually freeze, and for how long? Node times the same chain and reports its cost, but a browser might run WebCrypto off the main thread — «seconds of work» and «seconds of a dead UI» are different claims, and only a browser can tell them apart.

Open it from disk — double-click the file, or serve it from any static server. It is a plain script with no imports on purpose: it must run without a build, and Vite's dev server refuses to serve files from outside its root.

It reproduces the export/verify chain at container scale with plain Web APIs: the same operations on the same volumes as backup.ts — canonical serialization, one AES-GCM pass over the whole body, base64, SHA-256, then the reverse plus a per-record decrypt. It deliberately does not import the app; the subject is the platform, and a bundle would only add its own noise.
